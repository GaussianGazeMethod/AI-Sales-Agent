# 完整合成展示案例

所有机构、身份、联系ID、金额和时间均为虚构。机器可读源在 [sales_cases.json](../backend/examples/sales_cases.json)，启动时 `seed.py` 将其预置到本地数据库。预置记录用于查看完整历史和适配数据结构，**不是 AI 实际回放或语义质量通过证明**。

## 1. 登录后的数据

| 入口 | 内容 | 展示重点 |
|---|---|---|
| 示例学院甲 / 综合评价平台建设 | 当前方案报价，方案完成、报价未完成 | 双条件分别判断，未完成不整项勾选 |
| 示例学院甲 / 教师培训试点 | 另一个阶段一项目 | 同客户多项目隔离 |
| 示例学院乙 / 教师评价平台直采 | 七阶段至24万元签约 | 直采、范围缩减、预算/合同、历史证据 |
| 示例学院丙 / 学生评价平台分期建设 | 七阶段至57万元签约 | 需求、分期、招标、预约与签约区别 |
| 练习线索学校丁 | 销售负责，待实际核实验证 | 四项录入后的联系与属实确认 |
| 练习公海学校戊 | 未指派 | 管理分配与领取 |

日期按启动日向前回推，避免固定日历年让所有演示都变成超期。后续重复启动按客户/项目识别已存在样例，不覆盖用户对它们的操作。

## 2. 闭环一：从新线索到有效商机

使用销售账号，新建独立练习客户，避免复用已转商机记录。

| 步骤 | 输入或操作 | 核对结果 |
|---|---|---|
| 1 | “录入演示客户己，联系人演示主任，职位信息中心主任” | 追问缺失来源，不编造渠道 |
| 2 | “来源是市场活动” | 合并四项，建立本人线索；电话不作为最小录入前提 |
| 3 | “电话没接通” | AI 保留待验证，不当作明确拒绝 |
| 4 | “已通话，对方同意下周汇报” | 已有认可意愿；若未核实资料，继续追问信息是否属实 |
| 5 | “客户和联系人信息已核实属实” | 承接短答，保留意愿，转同一 Lead 为阶段一 |
| 6 | 进入商机，查看转化前记录 | 来源、联系人和核实依据保留，线索回收停止 |

否定对照用独立练习记录：明确资料不实或明确拒绝应记无效；后续重新联系在原记录上重新验证。传统表单与 AI 验证口径差异见 [闭环一](../spec/doing/02-闭环一-线索获取与验证.md)。

管理账号可将公海练习记录分配给销售，检查归属、期限和分配日志；销售不应获得管理分配权限。

## 3. 案例甲：同客户两个项目

综合评价平台的方案已完成，报价仍在准备；教师培训为独立项目。对话选定平台项目后反馈培训进展，不应自动把培训事实写进平台档案。未能确定归属时应澄清。

检查平台阶段三的方案/报价分项、历史阶段一二证据，以及客户页下两条项目的阶段和金额分别显示。

## 4. 案例乙：直接采购及范围调整

| 顺序 | 事实 | 阶段及金额边界 |
|---|---|---|
| 1 | 客户资料属实，负责人同意汇报并提供演示联系ID | 有效商机 |
| 2 | 实际拜访、确认教师评价需求，整理并确认需求报告，约下次沟通 | 客户触达 |
| 3 | 方案和32万元报价完成，客户确认 | 方案报价 |
| 4 | 最终方案确认，学校自有资金当期可用 | 经费确认，保留32万元依据 |
| 5 | 立项报告与管理会通过，随后缩减范围至24万元 | 不删除旧预算与经费证据 |
| 6 | 直接采购材料齐备，审核意见处理，采购审核通过 | 不虚构招标与答辩 |
| 7 | 双方合同评审与签约完成，合同24万元 | 登记签约、生成合同/交接；不自动记回款 |

## 5. 案例丙：分期、招标与签约

| 顺序 | 事实 | 需区分 |
|---|---|---|
| 1 | 四项、信息核实、认可意愿及直接联系 | 录入与验证分别完成 |
| 2 | 拜访后只有AI评价方向，继续明确学生综合素质评价 | 不只凭产品兴趣生成完整需求 |
| 3 | 资料用于设计，需求报告确认；汇报预约更正 | 资料已用与未来汇报未执行 |
| 4 | 实际汇报，方案及60万元报价均完成并确认 | 方案/报价两个条件 |
| 5 | 一次整体签约分两期；一期15万元可用，二期45万元资金未知 | 整体合同、交付、资金分别表达 |
| 6 | 立项方案还需补充覆盖范围和计划 | 汇报完成不等于过会 |
| 7 | 修改获认可，管理会正式通过 | 有来源的过会事实 |
| 8 | 公告发布，材料准备 | 无采购结果 |
| 9 | 已投标，按要求准备答辩、处理意见 | 投标完成不等于中标 |
| 10 | 取得中标通知书，57万元 | 已中标，尚未签约 |
| 11 | 合同递交，盖章流转中 | 递交完成，签约未完成 |
| 12 | 双方明确签约，合同沿用57万元 | 不推算最终分期拆分，不新增回款 |

检查已签约后的阶段耗时停止、历史金额变更、完整跟进和阶段证据。签约生成交接不代表交付已经启动。

## 6. 需求报告与诊断示例

可在案例甲主动请求需求报告或项目诊断；需要模型配置。报告保留五项结构、引用和未知，不用案例文档当其他客户的事实。

诊断建议只有采纳后才进入行动。执行行动时填写实际结果，再次诊断应读到反馈；不能把点击采纳当动作已发生。

## 7. 失败和重试走查

- 无模型密钥：普通数据页面可看，AI 提示不可用。
- 同 request_key 重试：不重复跟进或行动。
- 模型阶段判断失败但记录已保存：保留记录，明确未完成阶段操作。
- 其他销售无权限项目：拒绝读取和修改。
- 不存在的引文：拒绝相应候选，不编造来源。

## 8. 如何替换成自己的示例

修改 JSON 中的客户、项目、字段、分阶段事件和金额，并同步案例文档。保持每个已预置完成阶段有相应事件，签约金额明确且不等于回款。先在全新演示库检查；已有库不会因修改 JSON 自动覆盖同名项目。
