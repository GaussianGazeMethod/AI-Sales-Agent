# 接口说明

## 1. 完整契约

[OpenAPI JSON](api/openapi.json) 从当前 FastAPI 应用生成，不依赖运行数据库中的客户数据。在线契约在后端 `/docs` 与 `/openapi.json`，适配代码后重新导出，避免静态文档落后。

API 前缀为 `/api/v1`，业务请求使用 `Authorization: Bearer <access_token>`。错误通常包含 `detail` 和业务 `code`；400/422表示参数或业务输入，401未认证，403越权，409状态/版本冲突，503 AI 不可用，具体以契约和接口实现为准。

## 2. 主要业务接口

| 目的 | 方法与路径 |
|---|---|
| 登录/当前用户 | POST `/auth/login`、GET `/auth/me` |
| 来源等字典 | GET `/dicts` |
| 线索列表/录入 | GET/POST `/leads` |
| 查重 | POST `/leads/check-duplicate` |
| 分配/回收/领取 | POST `/leads/assign`、`/leads/recycle`、`/leads/{id}/claim` |
| 联系人 | GET/POST `/leads/{id}/contacts` |
| 跟进/验证 | GET/POST `/leads/{id}/followups` |
| Excel/批次 | POST `/imports/leads`、GET `/imports/batches` |
| 客户与商机 | GET `/customers`、`/opportunities`、`/opportunities/{id}` |
| 逐阶段依据 | GET `/opportunities/{id}/stages/{stage}/progress` |
| 阶段推进/签约 | POST `/opportunities/{id}/stage/advance`、`/opportunities/{id}/stage/sign` |
| 会话 | POST `/ai/conversations`、POST `/ai/conversations/{id}/messages` |
| 项目档案 | GET `/ai/assistant/projects/{id}/dossier` |
| AI状态 | GET `/ai/status` |
| 行动 | `/sales-actions` 及对应反馈接口 |

阶段候选、人工确认、报告、风险、评审、回款、目标与看板的完整路径和请求结构以 OpenAPI 为准。共用系统接口可能要求未提供的管理员角色，不会因为契约中存在就对演示经理开放。

## 3. 最小请求样例

```bash
curl -X POST http://127.0.0.1:8020/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"sales","password":"123456"}'
```

把返回的访问 Token 用作后续 Authorization。新建聊天会话：

```json
{}
```

发到 `/ai/conversations/{conversation_id}/messages`：

```json
{
  "request_key": "client-generated-unique-request-id",
  "content": "录入演示客户己，来源市场活动，联系人演示主任，职位信息中心主任"
}
```

客户端重试同一消息时复用 request_key；新消息使用新键。项目选择通过真实授权 ID 传递，不能相信模型生成的 ID。

## 4. 调用边界

区分 HTTP 成功、对话继续、候选生成、业务写入和部分成功。读具体返回中的任务、回执与状态，不用最后一段自然语言推断是否签约或阶段已推进。状态迁移和权限仍由后端决定。

## 5. 导出最新契约

在后端虚拟环境、`backend` 工作目录执行：

```bash
python -c "import json; from pathlib import Path; from app.main import app; Path('../docs/api/openapi.json').write_text(json.dumps(app.openapi(), ensure_ascii=False, indent=2), encoding='utf-8')"
```

该导出只读取应用声明，不需要对业务数据库执行请求。
