# 03 · 闭环二：商机跟进与签单

## 1. 与闭环一的衔接

有效商机就是阶段一，同一 Lead 继续推进。客户 Customer 与项目 Lead 分层，同一客户可以有预算年度、对象及范围不同的多个项目，各自维护证据、金额与行动。

## 2. 七阶段与完成标准

| 环节 | 名称 | 完成标准 | 核心目标 | 停留时长（自然日） |
|---|---|---|---|---|
| 一 | **有效商机** | ① 客户信息正确真实，且拿到**关键决策人（董事长/校长/中层主任）的直接联系方式**<br>② 完成**电话触达 / 添加微信并发送公司及产品简介** | 获取高质量潜在客户信息，并初步验证真实性 | **7** |
| 二 | **客户触达** | ① **上门拜访或线上会议**，向关键决策人或中层**汇报方案**<br>② 获取初步需求/痛点，由AI根据销售提供事实整理**一页《客户需求分析报告》**；预算未知标待了解，不单独阻止进入方案报价<br>③ **约定下一步见面沟通** | 建立初步信任，了解客户概况 | **10** |
| 三 | **方案报价** | ① 针对初步需求完成**建设方案和报价**<br>② 与客户**反复确认**设计方案和报价 | 深入诊断客户痛点，形成初步解决方案 | **15** |
| 四 | **预算确认** | ① 围绕最终需求**再次提供最终解决方案**<br>② 与**关键决策人再次确认经费** | 明确预算范围，确定解决方案 | **10** |
| 五 | **项目过会** | ① **协助客户编写立项报告**<br>② **获得立项会结果，针对结果做下一步** | 推动客户内部立项 | **20** |
| 六 | **招标采购** | ① 准备招投标文件及方案 / 直接采购材料<br>② 按实际采购流程准备投标答辩（不适用时无需完成）/ 处理直接采购审核意见<br>③ **获得招投标结果 / 直接采购审核通过结果（硬门槛）** | 按客户采购方式主导或参与采购流程（**不论是否招标都要走**） | **20** |
| 七 | **合同签约** | ① 双方明确完成签约，可作为合同条款一致及内部评审/签约流程完成依据，不重复追问仪式<br>② 登记合同金额与签约日期<br>③ 发起运营交付交接，交付启动状态单独记录 | 销售收口并交接至闭环三；项目启动由闭环三承接 | **8** |
| | | | **合计** | **90 天 = 3 个月** |


默认阶段停留为 7/10/15/10/20/20/8 个自然日，属于演示业务基准，不是所有行业的法定时限。实际执行读取数据库生效标准 `cfg_stage_standard`；初始值来自 `core/dicts.py`。采购答辩按实际流程适用，直接采购不虚构投标。

## 3. 证据与推进

每条标准记录来源、原文、达成时间和操作者。AI 候选与真实达成分别存储，PC 由负责人采纳；聊天执行按其实际回执和依赖校验写入，不用模型回复代替结果。已达成项保持原证据和时间，正常金额/范围调整不回退阶段。

逐阶段校验未完成项和硬门槛。一次历史补录可以携带多个阶段事实，但不能跳过没有证据的中间阶段。历史阶段可在详情中点击查看标准、依据及流转时间。

## 4. 方案与报价固定条件

建设方案完成、报价完成是独立三态：completed/not_completed/unknown。`core/sales_rules.py` 定义条件 ID 与 AND；任一未知或未完成都不能把整项标完成。引文分别定位到来源跟进，首次发生时间与最近确认时间分开。适配时同步改 Schema、Prompt、结构规则与两入口执行。

## 5. 跟进六项与档案

记录实际发生时间、项目归属、行动目标、客户反馈、达成情况、下一步。未知允许保留，不为了齐表反复追问。补答合并同一次行动；另一次实际联系新建跟进。客户反馈与销售判断、内部准备分开。同客户多项目分别归档，含糊时先确认归属。

项目档案维护最新事实、事件来源和修订；历史补录不覆盖较新当前值。需求报告、诊断和待办读取同一项目档案与相关原文。

## 6. 金额与签约

| 金额 | 语义 | 禁止推断 |
|---|---|---|
| 预算/区间 | 客户预算或项目规模 | 我方报价不能替代 |
| 方案报价 | 我方方案价格 | 客户认可不等于资金到账 |
| 当期资金 | 当前可用部分 | 不推断未来期资金已落实 |
| 中标/批准采购价 | 采购结果 | 不等于已签合同 |
| 合同金额 | 明确双方签约结果 | 不等于实际回款 |
| 回款 | 实际付款记录 | 不按签约金额自动生成 |

滚动修改保留改前、改后、原因、阶段和操作者。一次合同分期交付仍是一个项目，分期金额和付款安排未确认时保留未知；不能按最终总价比例倒算分期。

明确双方签约完成、有效证据和必填参数后，`stage_service.sign_contract` 登记签约，创建合同和交接。签约耗时按签约日期停止；不把交接生成说成交付启动。

## 7. 风险与卡单

使用 [R1–R6](13-R1-R6风险判断基准.md)：资金预算、信任、决策链、需求、项目节奏、产品价值匹配。风险有原文依据、当前状态、处理说明及解除历史，不能把缺字段机械等同风险。

规则性卡单、总时长和模型语义风险分开。R5 关注下一关键节点及预计时间；到期未完成且无新安排时提醒更新，不强制提前提供最终签约日期。风险不自动变成额外阶段硬门槛。

## 8. 行动闭环

诊断建议经销售选择、确认内容和时间后生成行动，保存诊断及建议索引，重复采纳不重复建。销售实际反馈后，完成行动与写跟进同事务。动作执行、目标效果与项目阶段完成分别判断；不能用普通提醒“完成”按钮绕过销售行动反馈。

## 9. 漏斗和预测

默认成交权重依次为 5%、12.5%、25%、40%、60%、80%、100%；按当前项目金额乘以权重。阶段四至六为演示估计值，需要用适配行业数据校准。漏斗按统一的状态、数据范围和期间汇总，不作为已经实现的收入。

## 10. 管理评审与团队节奏

管理人员核对五项：关键决策者、意向与资金、需求及确认人、决策相关方、竞争情况；记录通过/有风险/不通过、执行情况说明、结论和下次时间。周报可编辑，周会聚合卡单与待评审；AI 判断只供辅助，不替代管理者确认或自动形成绩效结论。

## 11. 丢单、回收与改派

丢单保留原因和说明，不删除历史。商机不执行线索七工作日回收，管理改派仍可留痕。阶段回退属于显式操作，不能由正常预算/合同变化自动触发。

## 12. 实现入口

阶段与签约：`api/opportunities.py`、`services/stage_service.py`；候选采纳：`stage_confirmation_service.py`；档案：`dossier_service.py`；行动：`sales_action_service.py`；风险：`risk_service.py`；管理评审与周报：`review_service.py`、`report_service.py`；界面：`OpportunityDetail.tsx`、`SalesActions.tsx`、`CompletedStandardReview.tsx`。

## 13. 适配与验证

阶段数量、标准、权重、硬门槛和采购路径不能只改显示文字。按 [适配开发指南](../../docs/适配开发指南.md) 同步修改枚举、默认规则、服务、Schema、Prompt、Skills 和界面。合成完整场景与预期边界见 [展示案例](../../docs/展示案例.md)，业务测试清单见 [业务用例](24-AI助手TDD业务用例集.md)。
