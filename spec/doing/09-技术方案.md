# 09 · 技术方案与运行约定

## 1. 技术栈

| 层 | 实现 |
|---|---|
| 前端 | React 18、TypeScript、Vite、Ant Design、React Query、Zustand |
| 后端 | Python 3.12、FastAPI、Pydantic、SQLAlchemy 异步会话 |
| 本地持久化 | SQLite、aiosqlite |
| 身份 | bcrypt、JWT |
| AI | Agently、agently-stage、OpenAICompatible provider、YAML Prompt |
| 导入导出 | openpyxl；需求报告 DOCX 由接口打包生成 |

具体约束以 `web/package.json`、`package-lock.json`、`backend/requirements.txt` 为准。展示版基于公共 Python 镜像，启动不依赖本机预制镜像。

## 2. 本地服务

前端 `127.0.0.1:5230`，Vite `/api` 代理到 `127.0.0.1:8020`；后端接口前缀 `/api/v1`，`/health` 用于健康检查，`/docs` 和 `/openapi.json` 为运行时契约。CORS 需和实际浏览器地址一致。

## 3. 配置来源

`app/config.py` 集中定义 Settings，读取当前后端工作目录下 `.env` 和环境变量。配置键、默认值、类型和影响见 [适配指南](../../docs/适配开发指南.md)。密钥只放在运行环境；`.env.example` 不含可用密钥。

模型配置采用 extract/dialogue/diagnose/compose 别名、model_profiles 和 api_key_pools。替换供应商需同步检查 provider 协议、参数、模型能力与错误响应；不能只替换 URL 就宣称兼容。

## 4. 数据与金额

所有金额存整数分，显示转换在统一格式工具中进行。SQLite 下枚举存字符串、结构化事实存 JSON、日期与审计时间区分；实际字段见 [数据模型](05-数据模型-表结构.md)。改数据库类型需复查 SQLite 专用 PRAGMA、补列和建表逻辑。

## 5. 认证与权限

登录返回访问与刷新 Token，接口从 Authorization Bearer 读取当前用户。数据过滤与编辑权限在后端执行。部署需自行生成 SECRET_KEY 并更换演示凭证。前端不会自动扩大后端角色能力。

## 6. 依赖安装与 Docker

README 提供 Python 虚拟环境和 npm 安装命令。Dockerfile 构建后端并携带 Skills、规则及文档依赖；Compose 将本地端口绑定到环回地址，并用独立数据卷保存 SQLite 和上传文件。前端仍按 README 单独启动。

## 7. 扩展与升级

先明确业务规则和 API 契约，再调整领域服务，最后同步 AI 契约和界面。保留来源、事务、幂等和角色边界。框架升级后验证结构化输出与 Skill 装配，不能仅凭导入成功替代业务验证。

SQLite 原型使用建表和补列，不具备完整生产迁移版本链；多人生产系统适配应引入明确迁移方案。当前未提供完整企业部署、外部 IM 或语音识别配置的开箱实现。

## 8. 验证

确定性回归使用临时数据库，不依赖运行中的业务库；有模型替身的用例只验证宿主契约。模型语义、外部供应商、浏览器交互和报告分页分别验证，见 [用例与验证](24-AI助手TDD业务用例集.md)。
