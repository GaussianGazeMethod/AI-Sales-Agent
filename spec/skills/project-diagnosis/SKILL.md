# 项目诊断分析

## 统一执行与交接

遵循 [统一交接契约 v1](../shared/contract.md) 及其JSON Schema；首次处理任务或跨skill交接时读取，已加载则复用。它规定职责、规则优先级、任务恢复和部分失败处理。具体能力以运行 API、Schema 和实际回执为准。


## 目标

帮助销售理解项目为什么能推进或卡住、现在优先做什么。说人话、给依据，不重复整个项目档案，不靠字数体现价值。

用于用户主动请求诊断、推进建议、拜访准备，或重要进展变化后的针对性分析。普通跟进保存后不默认输出长报告。由路由层确定任务与范围，不擅自扩大到所有客户。

## 读取与分析

通过 [项目档案管理](../project-dossier-management/SKILL.md) 取得当前项目摘要、相关事实及证据。需要时逐层展开，不默认读取全部历史；skill文件只提供方法，实际检索需调用系统工具。

阶段判断读取系统生效基准及当前完成证据；需求来源为 [闭环二规范](../../doing/03-闭环二-商机跟进与签单.md)，不能凭阶段名称猜完成条件。风险按需读取 [已确认R1–R6基准](../../doing/13-R1-R6风险判断基准.md)。

内部分析必须覆盖现状、缺口、阻点与风险、策略、行动五项。对照本次任务聚焦当前关键问题：

- 分清客户确认事实、销售判断、AI推断及未知。
- 阶段基准缺口不自动等于已发生风险；超期也不直接等于信任不足或需求不清。
- 风险已解除的，不因为历史原文重新当作未解除；有新事实再次发生时说明新依据。
- 区分动作完成、目标效果、阶段完成。正常方案完善不直接判断R4。
- 有历史诊断时突出新变化及原行动执行反馈；没有历史基线就不编造“较上次改善”。
- 资料不足时明确判断限制，仅问影响当前结论的关键问题；能给部分判断就先给，不索要整份档案。

## 固定报告结构

简版和详细版都保留以下五个栏目，空项简短注明，不编造内容填满：

| 栏目 | 输出要求 |
|---|---|
| 项目现状 | 当前阶段及最新关键变化；仅包含影响本次判断的范围、金额或客户态度 |
| 推进缺口 | 当前最重要的缺项，对应阶段标准或客户确认，不重复历史过程 |
| 阻点与风险 | 说明具体影响及依据；确无明确风险时写“暂无明确风险”，有信息限制则注明 |
| 推进策略 | 当前优先突破方向及简短理由，围绕客户需求，不写“加强沟通”等空话 |
| 下一步行动 | 1–3项具体动作、已知时间和预期获得结果；未知时间标待确认 |

同一事实只讲一次：缺口说缺什么，风险说影响，策略说怎么解决。不能为了列R1–R6输出六段无关内容。不编造成交概率、客户心理或合同承诺。

默认简版，每项以一句或短条表达。用户要求详细时，在同样五项结构中补充关键依据和推理，不改成长篇流水账。

## 一页详细报告约束

详细版正文以约800个中文字符以内为编辑目标，但字数不是分页保证。报告采用A4、常规页边距、正文11–12磅，标题、表格及短证据引用一起计入一页；不得缩小字号挤内容。

导出Word时通过可用文档工具生成并渲染检查分页；超过一页先删重复、压缩历史、只保留重要事项，再检查。无法验证分页时说明尚未验证，不声称保证一页。实际Word制作使用环境可用的文档能力，本skill不假设特定导出工具存在。

完整档案、附件和长原文通过证据链接另行查阅，不塞入报告，也不以附加长篇正文规避一页限制。

## 建议与业务执行边界

诊断结论和建议保存为分析结果，不能写成客户已确认事实。每条重要结论关联证据；推断注明推断，未知注明未知。

诊断提出的行动由销售采纳后进入待办；销售自己已明确的下一步按跟进规则自动承接。已有待办引用/更新，不重复生成。

本skill不直接通过分析推进阶段、改金额、解除风险或登记签约。将已识别事实及证据交给对应工作流程，由系统规则和工具校验执行；不得把“建议推进”伪装成已完成操作。

## 示例：示例C10月30日

**项目现状**：正式立项方案已汇报，校长要求修改后再安排上会。

**推进缺口**：需补学生覆盖数量和“一生一档”实现时间，最终方案尚未确认。

**阻点与风险**：当前是方案完善，不直接判为需求不清；具体人数和时间仍待方案补充。

**推进策略**：先补齐校长明确要求，拿到确认后再落实上会安排。

**下一步行动**：协调修改方案，11月2日反馈；确认后跟进上会时间。

此示例为讨论场景，不是真实系统记录，也不构成写入授权。
