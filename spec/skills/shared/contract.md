# 四个skill统一交接契约 v1

这是Host交接规范；各模型节点只输出本步骤实际声明的Schema，不承担完整Host控制字段。本文所述state/facts/operations/handoffs是逻辑交接概念，不是当前所有节点共用的模型Schema。模型必须遵循请求中实际提供的输出契约；若契约没有operation/tool-call字段，不得自行输出虚构的工具调用或执行回执。当前业务操作由Host依据结构化结果调用后端服务并核验回执。实现状态由交接记录说明，不由本规范声称。结构定义见[contract.schema.json](contract.schema.json)。它校验消息形状，不替代权限、业务规则、事务和实际服务结果验证。

## 统一分工

| Skill | 负责 | 不负责 |
|---|---|---|
| 线索录入与验证 | 四项收集、意愿验证、线索行动及转商机请求 | 商机阶段推进、项目摘要维护 |
| 项目进度跟进 | 六项跟进事实、必要补问、阶段证据及推进请求、销售行动 | 直接维护摘要、独立生成全面诊断 |
| 项目档案管理 | 原始记录/结构化事实的唯一归档入口、摘要、历史和检索 | 决定阶段、解除风险、直接创建待办 |
| 项目诊断分析 | 五项有依据的分析、优先策略和行动建议 | 把建议写成客户事实、直接推进阶段或创建未采纳建议待办 |

路由层维护任务、挂起/恢复、对象定位和顺序交接；工具执行层承担鉴权、幂等、状态机、并发版本和事务。所谓“唯一归档入口”是职责定义，不要求数据库复制原始消息；已有记录可通过ID关联。

## 规则来源与版本

- 线索规则：`spec/12-线索管理简化讨论.md`。
- 风险规则：`spec/13-R1-R6风险判断基准.md`。它优先于spec/03旧风险描述及旧skill“待讨论”文字。
- 阶段标准：系统当前生效版本；spec/03提供设计来源，不能把风险文档当阶段基准。

每次交接携带规则版本标识。若已确认需求与运行工具支持的规则版本冲突，返回`RULESET_MISMATCH`，保留事实并明确未执行的判断/操作，不假称新规则已经生效，也不静默套旧口径。不因规范更新批量重判历史数据。

## 输入

`request_id`标识一次处理请求，`task_id`标识跨轮任务，`turn_id`标识当前轮；重试原请求保留request_id，新回答生成新request_id但保留task_id。

`context`包含运行模式、调用skill、当前对象、用户/会话标识、当前消息、事实时间、已有事实、待补问题、规则版本和可用工具能力。权限上下文及时间由系统提供，不能让模型自称拥有权限。

新线索允许object.id为空；所有已存对象写入前必须解析为唯一ID。跨项目操作不可沿用旧ID。

## 事实与更正

每个fact具有临时标识、主题键、值、性质、来源记录ID及原文、发生时间和记录时间。性质固定为`confirmed_fact / sales_observation / plan / inference / unknown`。这是语义性质，不代表AI已经独立验证销售所说事实。

金额值应包含amount_fen和金额性质；日期值应包含时间及确定性（confirmed/estimated/tentative/range/unknown）。不能仅用自然语言值替代需要计算的金额和日期。

`supersedes`指向被明确纠正的事实ID；历史补录只增加历史事实，不以记录时间覆盖较晚发生的当前事实。冲突放入missing，不自行选胜出事实。证据引用必须能解析至系统原记录或本轮消息，不能捏造持久化ID。

## 逻辑交接（非通用模型输出Schema）

跨节点的逻辑交接可包含`state`、`facts`、`missing`、`questions`、`operations`、`handoffs`及`reply`。这些职责字段仅在实际输出Schema声明时才由模型生成；其余状态与控制字段由Host从各节点结果及服务回执中组装：

- `facts`：本次提取的事实/事实更正，尚未归档时不能声称已保存。
- `missing`：关键缺口及其是否阻挡当前任务；未知但不阻挡的内容可以收尾并保留。
- `questions`：本轮必要补问，每轮由主节点最多提出一个必要问题。
- `operations`：拟操作及真实执行回执，按操作分别记录状态，不能仅给总体成功。
- `handoffs`：目标skill、业务对象、事实ID、操作ID和交接原因；系统传递事实原文及上下文，不能只传一句摘要。
- `reply`：给销售的简短自然语言，不把内部契约JSON当日常界面。

`operations.arguments`是逻辑操作请求的Host-side表示。只有实际节点Schema明确声明该字段时模型才可输出；参数由Host及相应后端服务进一步校验。通用契约不代替服务参数契约。

操作名是运行环境提供的能力标识，本契约不虚构HTTP接口或暗示模型可直接调用服务。由Host执行的操作必须指定对象、来源、去重键及前置版本；新对象创建成功后其他Host操作才可引用返回的ID。

## 任务状态与恢复

`collecting`收集→`awaiting_user`等待补问→`ready`可处理→`executing`执行→`completed`完成；可转`partial`部分完成、`blocked`受阻或`suspended`话题切换挂起。

任务完成与业务对象完成不同：“未回复，待验证”也可结束本次记录任务，不等于线索验证结束。`completed`要求本轮必要操作有确定结果；真实写入不能在所有操作仍planned时完成。simulation可用completed表示模拟回答完成，但不得发送写操作或伪造成功回执。

路由持久化task_id、对象、待补问题、事实ID和已成功操作ID。短回答承接待补问题；明确更换对象时挂起原任务，新建或恢复目标任务；恢复前重读最新对象版本。

## Host服务结果、幂等与失败

Host操作状态：`planned / succeeded / failed / unknown / skipped`。只有后端服务返回可核对结果，Host才标succeeded并关联返回记录ID。失败含code、message、retryable。模型不得自行声明服务结果。

- 权限不足、对象不唯一、参数不合法、基准不符：停止对应操作并说明具体限制，不能用AI文本绕过。
- 版本冲突：重读后合并；不以旧摘要覆盖新事实。
- 超时结果未知：先凭去重键查询结果，不直接重发可能已成功的写操作。
- 跟进已保存而待办失败：返回partial，保留成功ID，只恢复失败步骤，不重建跟进。
- 必需服务未提供：Host返回CAPABILITY_UNAVAILABLE及未完成范围，不向销售多问本可由系统处理的信息。
- 若schema可通过但引用不存在、对象越权或证据不符，仍应被服务端拒绝。

## 典型交接

跟进节点按实际Schema输出事实候选；Host校验后调用档案服务并取得记录ID，再调用阶段/待办服务，随后把真实回执及最小必要事实交给后续节点。模型没有显式的服务调用Schema时，不生成archive_facts等工具请求。诊断结果由Host按需保存；建议被用户采纳后由路由交给跟进能力，去重复用现有待办。


## 辅助能力：一页需求报告

`project-requirements-report`负责五项需求报告编写，不直接推进阶段或归档；由跟进或路由按需触发，档案服务保存报告版本和来源。它不是新增核心业务入口。统一契约skill枚举包含该辅助能力；Host将report正文、版本、截至时间和source_ids交给档案服务校验，不将报告结论整体转成新客户事实，也不要求模型生成本步Schema未声明的写入调用。模型不直接执行archive_facts操作，保存动作由Host档案服务完成。
